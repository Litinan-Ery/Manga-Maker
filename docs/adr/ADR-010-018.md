# Manga Maker v0.3 架构决策 ADR-010～018

状态：Accepted for implementation。以下决策约束 v0.3 新代码，但不代表相应功能已经交付。兼容期统一从 MM-023 开始，直到各条记录列出的删除条件全部满足；没有证据时保持旧路径可读并失败关闭。

## ADR-010：PageLayoutDraft 是 Prompt 与生成的上游审批对象

- 选择：为每页建立版本化 PageLayoutDraft，先校验 frame、阅读顺序、焦点、人物位置、文字/crop-safe zone，再创建 PromptPackage/GenerationSpec。
- 拒绝：所有格子先用统一竖图尺寸生成，再由页面事后裁切。
- 兼容期：v0.2 PageVersion 可导入为 `imported_legacy` 草稿供查看；不自动产生 LayoutApproval。
- 回滚：关闭 v0.3 新 Job 写入口，保留旧工程的只读/历史导出；不删除已创建的 layout artifact。
- 删除条件：MM-034 关闭新项目旧入口，MM-044/059 的旧工程迁移与恢复通过，MM-060 回归通过。

## ADR-011：PromptPlan 保留多角色结构，ProviderExecutionSpec 承担供应商映射

- 选择：PromptPlan 保存 base、每角色独立正负区块、动作、order/center 与 relationship action；NovelAI 私有字段只存在于 production adapter 的 ProviderExecutionSpec。
- 拒绝：把所有角色 Tags 扁平拼入一个 prompt，或从扁平字符串反向推断角色。
- 兼容期：v0.2 PromptPackage 标记 `legacy_flat_prompt`，可查看/复现历史素材；多角色新 Job 必须重新编译 v2。
- 回滚：停止 v2 Job 创建，保留 canonical fixture 和已冻结 spec；不得把 v2 数据降格扁平后继续执行。
- 删除条件：MM-035～037、MM-045、MM-060 通过，所有写入者不再创建 legacy flat prompt；历史读取 adapter 仍按工程包兼容政策保留。

## ADR-012：Asset ready、Finding、ReviewDecision 与 PageApproval 分离

- 选择：供应商文件校验成功只产生 ready AssetVersion/Candidate；规则只产 Finding；用户明确决定 accepted/rejected/needs_fix；页面另行批准。
- 拒绝：供应商成功自动激活素材，或自动质量分数直接批准页面。
- 兼容期：v0.2 ready 素材可进入 legacy CandidateSet，但不自动 accepted；历史页面可恢复，不冒充 v0.3 正式发布批准。
- 回滚：保留候选和证据，关闭正式 v0.3 导出；旧历史导出维持只读可用。
- 删除条件：MM-038～043、MM-058、MM-060、MM-062、MM-064～065 通过，并完成 v0.2 恢复演练。

## ADR-013：SQLite durable work/outbox，不引入外部 broker

- 选择：单 SQLite 保存 work item、lease、outbox、handled event；本机 worker 默认串行且幂等。
- 拒绝：仅用进程内 task 作为真源，或引入 Redis/Kafka 等外部服务。
- 兼容期：旧 generation queue 经 compatibility adapter 接入；原付费确认、暂停、取消和重启不自动续跑语义保持。
- 回滚：停 worker 并把未确定外部尝试转 `needs_review`；已提交业务状态和 outbox 不删除。
- 删除条件：MM-028/029/054/055/063 的租约、重放和崩溃矩阵通过，旧 queue 无写入者。

## ADR-014：文本模型按 stage/shard 与 TokenBudget 执行

- 选择：调用前冻结能力快照和预算，按阶段/分片持久检查点；截断或能力未知时失败关闭。
- 拒绝：整章单请求，静默裁剪硬约束，失败后整章无条件重跑。
- 兼容期：v0.2 一次性适配器保留给历史 Mock 回归；v0.3 长章节真实生产不走该路径。
- 回滚：停止后续 stage 调度，保留 checkpoint、TruncationReport 和已付费结果供人工处置。
- 删除条件：MM-047～050、MM-061 的 Mock/恢复通过，并由 MM-051 在用户授权后完成真实验收。

## ADR-015：统一 Artifact Dependency Graph 计算最小失效

- 选择：稳定 ArtifactRef + 有类型 DAG 记录版本依赖；新上游版本只使可达下游决定 stale，历史不删除。
- 拒绝：各模块保存无统一解释的布尔 stale，或靠跨模块 cascade delete 清理。
- 兼容期：可证明的旧版本补边；无法证明的标记 `legacy_unknown`。
- 回滚：停止新增边和自动失效传播，保留图供诊断；业务硬门禁仍同步核验实际 hash。
- 删除条件：MM-030、MM-044、MM-063 的循环、最小影响、迁移和恢复测试通过。

## ADR-016：按业务能力纵向模块化，模块内部再分层

- 选择：每个模块同地拥有 contract/domain/application/ports/adapters/migrations；保持一个进程、一个发布物、一个 SQLite。
- 拒绝：全局 services/models/repositories 横向大层，或拆成微服务。
- 兼容期：现有 `adaptation/`、`generation/`、`pages/` 等由明确 legacy binding 包装，逐用例迁移。
- 回滚：切回 legacy facade binding；新模块文件和 additive 表保留但不参与写路径。
- 删除条件：MM-024 特征测试保持，MM-025～027 架构门禁通过，相关模块消费方和恢复 fixture 全部迁移。

## ADR-017：跨模块只用版本化公开契约，表由单一模块写入

- 选择：跨模块只导入 `public.py`/`contracts.py`；Command/Query/Snapshot/Event 不暴露 row、Request、供应商 payload 或绝对路径。
- 拒绝：因共用 SQLite 而直接跨模块读写私表，或共享可写业务模型。
- 兼容期：旧集中查询仅在有 owner/allowlist 的 compatibility seam 中存在，不可用于 v0.3 新 route。
- 回滚：恢复旧 facade 读取路径但禁止新写入；不回滚已提交的版本化公开数据。
- 删除条件：MM-026/027/045 的 import、table ownership、consumer fixture 和 migration registry 测试持续通过，compatibility allowlist 归零。

## ADR-018：Typed composition root 与架构适应性函数

- 选择：AppContainer 显式组装 adapter/facade/lifecycle；FastAPI 使用 Depends；CI 检查循环、禁止 import、表 owner、domain 纯净和前端 feature 边界。
- 拒绝：service locator、任意位置读取 `app.state`、可变全局 singleton 或只靠 code review 记忆边界。
- 兼容期：旧 route 可通过命名 provider 访问 legacy binding；v0.3 route 禁止新增 `request.app.state.*`。
- 回滚：composition root 可重新绑定 legacy facade；架构测试只允许带 owner、原因和删除条件的临时豁免。
- 删除条件：MM-025～027、MM-053、MM-045 通过，旧 route 已迁移且 allowlist 为空。
